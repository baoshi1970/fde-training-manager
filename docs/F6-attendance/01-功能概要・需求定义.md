# 01 功能概要・需求定义书

## 1. 目的

登记培训课次的出勤情况（出席／迟到／缺席），并能一览各课次的登记进度。

## 2. 用户与权限

- 使用者：登录后的管理员（admin）。沿用现有的 Spring Security 设置，F6 不新增角色。

## 3. 用语

| 用语 | 含义 |
|---|---|
| 课次 | 某课程在某日某时段的一次授课（F4） |
| 报名者 | 报名了该课程的学员（F5） |
| 出勤状态 | 出席（PRESENT）／迟到（LATE）／缺席（ABSENT） |
| 未记录 | 没有出勤记录。**不是状态值**，没有记录就是未记录 |

## 4. 功能需求

| ID | 需求 |
|---|---|
| R1 | 提供课次一览，显示每个课次的「报名人数」「已记录人数」和登记情况（无报名者／未登记／登记中／已登记） |
| R2 | 选择课次后，列出该课次所属课程的报名者，可逐人选择出勤状态（含「未记录」） |
| R3 | 登记页显示各状态人数（出席・迟到・缺席）和未记录人数 |
| R4 | 保存：已有记录则更新，没有则新增；同一课次・同一学员只能有 1 条 |
| R5 | 选「未记录」保存：没有记录时不新增；已有记录时删除记录 |
| R6 | 没有报名该课程的学员不能登记出勤；提交中只要含 1 个非报名者，整体拒绝，一条都不保存，并显示中文错误消息 |
| R7 | 提供「全部设为出席」按钮（仅改画面下拉框，点「保存」后才生效） |
| R8 | 课次排期画面的每行有「出勤」按钮，可直接进入该课次的登记页 |
| R9 | 删除课次时，连同该课次的出勤记录一起删除（不能因外键约束报 500） |
| R10 | 主菜单・主页的 F6 显示为已完成，入口为 `/attendance` |

## 5. 非功能需求

| ID | 需求 |
|---|---|
| N1 | 业务规则写在 Service，Controller 只做输入输出 |
| N2 | 违反规则抛 `BusinessException`，找不到数据抛 `NotFoundException`（→ 404） |
| N3 | 提交了非法数据（状态值不正确、字段名不正确）显示业务错误，不出 500 |
| N4 | 部署环境（Postgres・多实例）：不使用 static 缓存等进程内状态；`resetToSeed` 中出勤数据最先删除 |
| N5 | 画面文字、错误消息、注释用中文；测试数据使用 `@example.com` |

## 6. 范围外

- 取消报名时对出勤的处理（F5 的范围）
- 出勤率统计・进度看板（F9）
- 评分（F8）
- 出勤的修改履历・登记人记录
