## 2. S-ATT-01 课次一览

- URL：`GET /attendance`　模板：`attendance/list.html`

### 布局

```
出勤登记
选择一个课次，登记该课程报名者的出勤。
┌──────┬─────┬──────┬─────┬───────────────┬──────────┐
│日期  │时段 │课程  │讲师 │出勤登记情况   │操作      │
├──────┼─────┼──────┼─────┼───────────────┼──────────┤
│...   │...  │...   │...  │3 / 6 人已记录 [登记中]│[登记出勤]│
└──────┴─────┴──────┴─────┴───────────────┴──────────┘
```

### 显示项目

| 列 | 内容 | 格式 |
|---|---|---|
| 日期 | 课次日期 | `yyyy-MM-dd (E)` |
| 时段 | 开始–结束 | `HH:mm–HH:mm` |
| 课程 | 课程显示名 | `course.displayName` |
| 讲师 | 讲师姓名 | `instructor.name` |
| 出勤登记情况 | 见下表 | |
| 操作 | 「登记出勤」按钮 → `/attendance/{课次id}` | |

### 「出勤登记情况」的显示规则

| 条件 | 显示 |
|---|---|
| 报名人数 = 0 | 灰字「无报名者」（不显示徽章） |
| 报名人数 > 0，已记录 = 0 | 「0 / N 人已记录」＋徽章「未登记」（todo） |
| 报名人数 > 0，0 < 已记录 < 报名人数 | 「M / N 人已记录」＋徽章「登记中」（todo） |
| 报名人数 > 0，已记录 ≥ 报名人数 | 「N / N 人已记录」＋徽章「已登记」（done） |

- 没有课次时：显示一行「没有课次」。
- 排序：沿用 `SessionService.findAll(null)` 的顺序。

## 3. S-ATT-02 出勤登记

- URL：`GET /attendance/{sessionId}`　模板：`attendance/form.html`

### 布局

```
出勤登记                                   [返回课次一览]
S2 AI 辅助编码　2026-11-10 (周二) 19:30–21:00　讲师：○○

[出席 n] [迟到 n] [缺席 n] [未记录 n]       ← 报名者不为空时显示

┌─┬──────┬──────┬───────────┐
│#│学员  │所属  │出勤 [▼未记录]│
└─┴──────┴──────┴───────────┘
[保存]  [全部设为出席（保存后生效）]
```

### 显示项目

| 项目 | 内容 |
|---|---|
| 课次信息 | 课程显示名、日期、时段、讲师 |
| 统计块 | 出席・迟到・缺席人数（`counts`）＋ 未记录 = 报名者数 − 已保存记录数 |
| 学员行 | 序号、学员姓名、所属（`trainee.affiliation`） |
| 出勤下拉框 | `name="status_{学员id}"`；选项：`未记录`（空值）／出席／迟到／缺席；已保存的状态为选中 |

### 操作

| 操作 | 行为 |
|---|---|
| 保存 | `POST /attendance/{sessionId}`，成功后重定向回本画面，顶部显示「已保存出勤」 |
| 全部设为出席 | 前端 JS，把所有 `select[name^=status_]` 设为 `PRESENT`，不提交；需再点「保存」 |
| 返回课次一览 | 链接到 `/attendance` |

### 异常显示

| 场景 | 显示 |
|---|---|
| 报名者为空 | 表格内一行「这门课程还没有人报名」；不显示统计块、保存按钮、全部出席按钮 |
| 业务错误 | 重定向后显示 flash `error`（红色提示，由共通布局输出） |
| 课次不存在 | 404 页面 |
