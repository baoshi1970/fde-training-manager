# 05 程序设计书

## 1. 分层与类关系

```
AttendanceController (web)
   ├─ AttendanceService (service) ─┬─ AttendanceRepository (repository)
   │                               ├─ SessionService   （取课次、课次一览）
   │                               └─ EnrollmentService（取报名者・报名人数）
   └─ SessionService（画面上显示课次信息）

SessionService.delete ──▶ AttendanceRepository.deleteBySessionId（F6 追加）
```

规则：Controller 不写业务判断；业务规则全在 `AttendanceService`。

## 2. domain

### Attendance
- 字段：id、session（`CourseSession`，必填）、trainee（`Trainee`，必填）、status（`AttendanceStatus`，必填，`EnumType.STRING`）
- 唯一约束 `(session_id, trainee_id)`
- 构造器：`Attendance(session, trainee, status)`；`setStatus` 用于更新

### AttendanceStatus
- `PRESENT("出席")`、`LATE("迟到")`、`ABSENT("缺席")`；`getLabel()`
- 「未记录」不是枚举值

## 3. AttendanceRepository

| 方法 | 用途 |
|---|---|
| `List<Attendance> findBySessionId(Long)` | 取课次的全部出勤 |
| `long countBySessionId(Long)` | 已记录人数 |
| `void deleteBySessionId(Long)` | 删除课次时连带删除 |
| `boolean existsByTraineeId(Long)` | 判断学员是否有出勤（测试用） |
| `void deleteByTraineeId(Long)` | 删除学员时连带删除 |

## 4. AttendanceService（类级别 `@Transactional(readOnly = true)`）

| 方法 | 事务 | 说明 |
|---|---|---|
| `overview()` | 只读 | 对 `sessionService.findAll(null)` 的每个课次，组合 `SessionOverview(session, enrolled, recorded)`；`enrolled = enrollmentService.countByCourse(courseId)`，`recorded = countBySessionId` |
| `countByStatus(sessionId)` | 只读 | 返回 `EnumMap`：所有状态先置 0，再按记录累加 |
| `findEnrollments(sessionId)` | 只读 | `sessionService.get` → `enrollmentService.findByCourse(courseId)`；课次不存在时由 `get` 抛 `NotFoundException` |
| `findStatuses(sessionId)` | 只读 | 学员id → 状态 的 Map |
| `save(sessionId, statuses)` | **写** | 见下 |

### save 的处理流程

```
1. session = sessionService.get(sessionId)              // 不存在 → NotFoundException
2. enrolled = 该课程报名者的 { 学员id → Trainee }
3. 遍历 statuses.keySet()：
       不在 enrolled 中 → throw BusinessException（整体拒绝，尚未改动任何数据）
4. existing = 该课次已有出勤的 { 学员id → Attendance }
5. 遍历 statuses：
       status == null : existing 有 → delete；没有 → 不动
       status != null : existing 有 → setStatus（JPA 脏检查更新）
                        没有       → save(new Attendance(session, trainee, status))
```

- **校验先于写入**：步骤 3 在所有写操作之前，保证「一条都不保存」。
- statuses 中**没有**的学员不处理（不会被清除）。
- 错误消息（中文，含原因与对策）：`学员（id=X）没有报名「课程名」，不能登记出勤。请先在报名管理里报名`

## 5. AttendanceController

| 方法 | 映射 | 处理 |
|---|---|---|
| `list` | `GET /attendance` | `overview()` → `attendance/list` |
| `form` | `GET /attendance/{sessionId}` | 放入 courseSession／enrollments／statuses／counts／options → `attendance/form` |
| `save` | `POST /attendance/{sessionId}` | `parse(params)` → `service.save`；成功设 flash `message`，`BusinessException` 设 flash `error`；都重定向回登记页 |

### parse（请求参数 → `Map<Long, AttendanceStatus>`）
- 只处理前缀 `status_` 的参数（`PARAM_PREFIX`）
- 值为 null 或空白 → `null`（未记录）
- 值用 `AttendanceStatus.valueOf` 转换；学员id 用 `Long.valueOf` 转换
- 转换失败（`IllegalArgumentException`，含 `NumberFormatException`）→ `BusinessException("提交的出勤数据不正确，请刷新页面后重试")`
- 这里只做「输入格式的转换」，不含业务判断（是否报名由 Service 判定）

## 6. 既有类的变更

### SessionService
- 构造器新增依赖 `AttendanceRepository`
- `delete(id)`：`get(id)`（不存在则抛 `NotFoundException`，此时不删出勤）→ `attendanceRepository.deleteBySessionId(id)` → `sessionRepository.delete(session)`

### TraineeService
- 构造器新增依赖 `AttendanceRepository`
- `delete(id)`：`get(id)`（不存在抛 `NotFoundException`）→ 有报名记录则 `BusinessException`（既有规则，此时不动出勤）→ `attendanceRepository.deleteByTraineeId(id)` → `traineeRepository.delete`
- 背景：取消报名只删报名记录，不删出勤；此前直接删学员会因外键报 500
- 选择「连同删除」而不是「有出勤就不能删」的理由：取消报名后出勤的学员已不在登记画面里（登记画面只列报名者），出勤无法再从画面清除，若禁止删除会变成永远删不掉

### DataInitializer
- 构造器新增 `AttendanceRepository`
- `resetToSeed()` 在 `lockIfPostgres()` 之后、`enrollmentRepo.deleteAllInBatch()` 之前，先 `attendanceRepo.deleteAllInBatch()`

### Feature
- F6：`done = true`，`path = "/attendance"`

## 7. 日期处理

- F6 不直接使用「今天」，没有 `LocalDate.now()` 的使用；无需注入 `Clock`。
